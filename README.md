# 无障碍路线核验台

一个可本地运行的 Web 工具：录入楼层节点、门宽、坡度与电梯连接，设置轮椅宽度与最大坡度后，
系统将可通行条件编译为图，计算节点间的可行路线；当最短路线不合规时，标出**首个不合规边**
并给出**替代路线**。每次核验结果（含当时的设置快照）都会保存，支持按楼层筛选与 JSON 导出。

## 快速开始（单条命令）

```bash
docker compose up --build
```

启动后访问：

- **Web 界面**：http://localhost:8000
- **API 文档（Swagger）**：http://localhost:8000/docs
- **端口**：`8000`（宿主机端口可在 `docker-compose.yml` 的 `ports` 中修改）

依赖安装、建表、默认设置写入均在容器启动时自动完成；数据库为空时会灌入一份演示数据
（含一扇过窄的门和一段过陡的坡道，便于直接体验「绕行」与「不合规」判定）。
SQLite 数据文件持久化在 `./data/app.db`，删除该目录即可重置。

## 本地运行（不用 Docker）

```bash
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

## 使用流程

1. **数据录入**：设置轮椅宽度（默认 750mm）与最大坡度（默认 8.33%）；
   添加楼层节点（名称 + 楼层）；添加连接，类型支持 走廊 / 门 / 坡道 / 电梯 / 楼梯，
   门与电梯填门宽、坡道填坡度。边列表会实时标注每条边的合规状态。
2. **路线核验**：选择起点与终点，系统计算路线并保存结果：
   - `可直接通行`：最短路线全部合规；
   - `需绕行`：最短路线存在不合规边，页面标出首个不合规边及原因，并给出合规的绕行路线；
   - `不可通行（需整改）`：当前设置下无完全合规路线，备选路线按整改代价从小到大排序；
   - `不连通`：两节点间不存在任何路径。
3. **核验记录**：查看历史核验（含核验时的设置快照，便于复核），支持按楼层筛选、
   删除，以及一键导出 JSON（`GET /api/export?floor=2F`）。

## 合规判定规则

| 边类型 | 规则 |
| --- | --- |
| 门 / 电梯 | 门宽 ≥ 轮椅宽度；门类型缺门宽视为无法核验（不合规） |
| 坡道 | 坡度 ≤ 最大允许坡度；缺坡度视为无法核验（不合规） |
| 楼梯 | 轮椅不可通行，恒不合规 |
| 走廊/通道 | 恒合规 |

## API 一览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET/PUT | `/api/settings` | 读取 / 更新通行设置 |
| GET/POST | `/api/nodes` | 节点列表（`?floor=` 筛选）/ 新增节点 |
| DELETE | `/api/nodes/{id}` | 删除节点（级联删除相关边） |
| GET/POST | `/api/edges` | 边列表（含合规状态，`?floor=` 筛选）/ 新增边 |
| DELETE | `/api/edges/{id}` | 删除边 |
| POST | `/api/checks` | 执行核验并保存结果 |
| GET | `/api/checks` | 核验记录（`?floor=` 筛选起点或终点所在楼层） |
| GET/DELETE | `/api/checks/{id}` | 查看 / 删除单条记录 |
| GET | `/api/export` | 导出全部核验记录为 JSON 文件（`?floor=` 可选） |
